# QQRT · 服务端部署方法与软件原理

> 手表端：Vela 快应用（包名 `com.qqrt.band`，v4.10.0）
> 服务端：Next.js 16 standalone + PGlite（进程内 PostgreSQL 18）+ QQ 官方机器人 SDK

---

## 一、为什么必须有一个服务端

QQ 没有对个人号开放任何第三方协议，**任何"手表直连 QQ"的方案都不可能合法跑通**。QQRT 走的是官方机器人通道：

```
   ┌──────────────┐    HTTPS/JSON     ┌────────────────────┐   WebSocket 长连接   ┌──────────────┐
   │ 手表快应用    │ ───────────────▶ │  QQRT 服务端        │ ◀──────────────────▶ │ QQ 开放平台   │
   │ 336×480      │ ◀─────────────── │  (你的服务器)        │                      │ 机器人网关    │
   └──────────────┘   轮询/发送指令    └────────────────────┘   事件推送/发消息      └──────┬───────┘
                                                                                        │
                                                                                  ┌─────▼──────┐
                                                                                  │ 好友 / 群聊 │
                                                                                  └────────────┘
```

服务端承担三件手表做不了的事：

1. **保管 AppSecret** —— 机器人凭证绝不能塞进手表（rpk 是明文包，任何人解包就能拿到）。
2. **维持长连接** —— 机器人网关是 WebSocket，手表休眠就断，必须由服务器 7×24 挂着收消息。
3. **媒体转码** —— QQ 的语音是 SILK、图片动辄几 MB，手表只有 336×480 的屏和极小的内存，必须转成 240px 图片 / WAV 音频。

## 二、软件原理

### 2.1 手表端（快应用）

| 部分 | 做法 |
| --- | --- |
| 页面 | `Login / Home / Chat / Ime / Settings / Members / Requests / Viewer` 八个页面，`designWidth: 336`，`deviceTypeList: ["watch"]` |
| 输入 | Vela 没有 `system.input`，所以移植了**喵喵输入法**（`Ime/ime.ux` + 本地词库 `dic.js`），走 `global.__imeText/__imeResult` 回传 |
| 消息列表 | `list` + `list-item`，**行高必须写死**（Vela 里 `text` 不会撑开父容器，动态高度会黑屏），气泡高度由"逐字符宽度模拟"算出来后写死 |
| 表情 | 手环固件没有 emoji 字形（显示成豆腐块），所有 emoji 预先切成 PNG 放在 `common/emoji/`，按 Unicode 查表 |
| 网络 | 只有 `system.fetch`，没有 WebSocket，所以**轮询** `GET /api/watch/messages?since=<seq>` |
| 图片 | 气泡里点一下 → `Viewer` 页全屏看大图（服务端已压到 240px，另有一份原图接口） |

### 2.2 服务端

- **Next.js Route Handlers** 提供两套 API：
  - `/api/watch/*` —— 手表用（`login / conversations / messages / command / media / fmedia / members / meta / msg-delete …`）
  - `/api/admin/*`、`/api/bot/*` —— 网页控制台用（登录、注册账号、绑定机器人、连接/断开）
- **PGlite**：PostgreSQL 18 编译成 WASM，**跑在 Node 进程里**，不需要装数据库、不需要连接串，数据就是一个 `pgdata/` 目录，拷走即备份。
- **drizzle-orm** 做 schema 与查询，`init.sql` 在首次启动时建表。
- **多用户隔离**：每个网页账号绑定自己的机器人，所有业务表带 `user_id`；网页用 session cookie 隔离，手表用自己的 token。

核心表：`users` / `sessions` / `settings`（加密后的 AppSecret）/ `conversations` / `messages` / `contacts` / `join_requests`。

### 2.3 收消息（QQ → 手表）

```
好友发消息
  → QQ 开放平台推事件到 WebSocket
  → botManager 解析（文本 / 图片 / 语音 / 视频 / 引用 / 表情）
  → 媒体下载到 data/media/in
  → ffmpeg 转码：图片 → 240px WebP/PNG；语音 SILK → WAV（+ 云端 ASR 出文字）；视频 → 分段 ≤50s
  → 写入 messages 表（seq 自增）
  → 手表轮询 /api/watch/messages?since=N 拿到裁剪后的轻量 JSON
  → 渲染气泡（表情查表换 PNG，图片走 /api/watch/media/:id/:idx）
```

### 2.4 发消息（手表 → QQ）

```
手表输入 → POST /api/watch/command
  → botManager 调开放平台发送接口（c2c / group）
  → 拿到 msg_id → 回写 messages.status（sending / sent / failed）
  → 4.5 分钟内可用"被动回复"（带引用），超时改走主动消息
```

### 2.5 安全设计

- 网页侧所有写操作走 `assertSameOrigin`（防 CSRF），并用 `QQRT_PUBLIC_ORIGIN` 校正反代后的 Origin。
- AppSecret 用 AES 加密后存 `settings` 表，密钥在 `data/secret.key`（丢了要重新绑机器人）。
- 手表侧 `/api/watch/login` 换 token，后续请求带 `Authorization`；短码登录支持 `#XXXX` 形式（手环键盘打不出 `?` `=`）。

## 三、部署方式（四选一）

### 方式 A · 本机 / 局域网（5 分钟，调试用）

```bash
cd server/qqrt-server
cp .env.example .env          # 改 PORT / PGLITE_DIR
npm ci
npx drizzle-kit push          # 建表
npm run build && npm start    # 或 npm run dev
```

- 访问 `http://127.0.0.1:3005`，默认管理员 `admin / qqrt123456`（首次登录后请改密码）。
- 手表填地址：同一 WiFi 用 `http://<电脑内网IP>:3005`，模拟器用 `http://10.0.2.2:3005`。
- **地址必须带 `http://`**，客户端没写协议会默认补 `https://`，那样连不上。

### 方式 B · WorkBuddy Sites 托管（当前线上这套）

线上地址：`https://qqrt-chat-server.apps.workbuddy.host/?sharecode=TFK3NX7DXP`

Sites 只给单端口 HTTP、且预检拒绝带 `pg` 的项目，所以做法是**预构建 + 运行时解压**：

```bash
cd server
bash make-bundle.sh       # 产出 sites-deploy/{bundle.tar.gz, ffmpeg.tar.gz, boot.mjs, package.json}
```

然后把这个目录作为项目发布，参数：

| 项 | 值 |
| --- | --- |
| installCmd | 留空（依赖已打进 bundle，`npm ci` 会 OOM） |
| startCmd | `node boot.mjs` |
| 端口 | 读 `PORT`，默认 3005 |

`boot.mjs` 首次启动解压 `bundle.tar.gz` → `runtime/`，之后用 `.bundle-stamp` 跳过解压（否则冷启动十几秒，平台探活会判"链接超时"）；ffmpeg 单独打包、后台解压，不阻塞启动。

> 注意：免费托管的**冷启动**会让第一次访问慢 5–20 秒，手表端表现为一次超时，重试即可。

### 方式 C · Oracle Cloud 永久免费 + Docker + 自动 HTTPS（推荐长期用）

`server/qqrt-server/deploy-free/oracle/` 已经写好一键脚本：

```bash
# 1. 开一台 Oracle Always Free 的 Ubuntu 22.04 实例（ARM 或 x86 都行），放行 80/443
# 2. 上传 qqrt-server 目录后执行：
cd qqrt-server
sudo bash deploy-free/oracle/setup.sh              # 自动用 <公网IP>.sslip.io 做域名
# 或用自己的域名（先把 A 记录指过去）：
sudo bash deploy-free/oracle/setup.sh qq.example.com
```

脚本会：装 Docker → 生成 `.env`（域名 + 随机 DB 密码）→ 起 `app + caddy` → Caddy 自动申请 Let's Encrypt 证书。
数据在 Docker 卷 `pgdata` / `appdata`，重建容器不丢。

### 方式 D · 任意 VPS / 群晖（手动 Docker）

```bash
cd server/qqrt-server
docker build -f deploy/Dockerfile -t qqrt .
docker run -d --name qqrt -p 3005:3005 \
  -e PORT=3005 -e PGLITE_DIR=/app/pgdata -e AUTO_MIGRATE=1 -e TZ=Asia/Shanghai \
  -v qqrt-pg:/app/pgdata -v qqrt-data:/app/data \
  --restart unless-stopped qqrt
```

前面套 Nginx/Caddy 反代到 `127.0.0.1:3005`，注意把 `request_body` 上限调到 100MB 以上（手表要传图/语音），读超时要大于 60s（长轮询）。

### 关键环境变量

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | HTTP 端口 | `3005` |
| `PGLITE_DIR` | 数据库目录 | `./pgdata` |
| `DATA_DIR` | 媒体/缓存目录 | `./data` |
| `MAX_UPLOAD_MB` | 单文件上限 | `200` |
| `QQRT_PUBLIC_ORIGIN` | 反代后的对外地址，修 CSRF | 空 |
| `AUTO_MIGRATE` | 启动自动建表 | 关 |
| `NEXT_PUBLIC_BASE_PATH` | 子路径部署时用 | 空 |

### 部署完的三步

1. 浏览器打开站点 → 用 `admin / qqrt123456` 登录 → 改密码（控制台支持注册新账号，每个账号一套独立数据）。
2. 「机器人」页填 QQ 开放平台的 **AppID + AppSecret** → 连接，状态变成"已连接"。
3. 手表端登录：服务器地址填站点地址（可只填分享码），账号密码同上。

## 四、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 手表提示「服务器拒绝(403)」 | 托管站有分享码门禁，地址要填**完整分享链接**（含 `?sharecode=`） |
| 一直「连接超时」 | 免费托管冷启动；或 `http://` 漏了被补成 `https://`；或反代读超时 < 60s |
| 报错 code 204 | 服务端返回空响应（多为未登录/路由未命中），检查 `QQRT_PUBLIC_ORIGIN` |
| 控制台「跨站请求被拒绝」 | CSRF 校验，设置 `QQRT_PUBLIC_ORIGIN` 为真实访问地址 |
| 手环上打不出 `?` `=` | 手环键盘布局限制，登录地址支持只填 `#XXXXXX` 短码 |
| 表情显示成方块 | 该 emoji 没进 `common/emoji/` 表，补 PNG 即可 |
| 语音没声音 | ffmpeg 未就绪（`/api/health` 里 `ffmpeg:false`），检查 `runtime/bin/ffmpeg` |
