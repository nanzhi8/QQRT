# QQRT 服务端 · 部署说明

服务端是 **Next.js 16 + PostgreSQL**，负责：QQ 机器人长连接、消息入库、手表端 REST 接口、图片/语音转码。

部署包结构：

```
qqrt-server/
├── src/                      # 源码（API + 业务逻辑）
├── deploy/
│   ├── deploy-qqrt.sh        # 裸机一键部署（Debian/Ubuntu，含 nginx + pm2 + postgres）
│   ├── install-debian.sh     # 只装系统依赖
│   ├── check-memory.sh       # 小内存机器检查
│   ├── nginx.conf.example    # 反向代理模板（含子路径 + WebSocket 头）
│   ├── Dockerfile            # 容器镜像
│   └── docker-compose.yml    # 应用 + PostgreSQL 一键起
├── .env.example              # 环境变量样例
├── start-publish.js          # 生产启动（读 .env、绑定 0.0.0.0:$PORT）
├── ecosystem.config.cjs      # pm2 配置
└── package.json
```

---

## 方式 A：Docker（推荐，最省事）

要求：装好 Docker + Docker Compose。

```bash
cd qqrt-server

# 1. 改密码：deploy/docker-compose.yml 里的 POSTGRES_PASSWORD 和 DATABASE_URL 要一致
vi deploy/docker-compose.yml

# 2. 起服务（首次会构建镜像，3~5 分钟）
docker compose -f deploy/docker-compose.yml up -d --build

# 3. 建表（只需第一次）
docker compose -f deploy/docker-compose.yml exec app npx drizzle-kit push --force

# 4. 看日志 / 健康检查
docker compose -f deploy/docker-compose.yml logs -f app
curl http://127.0.0.1:3005/api/health      # {"ok":true}
```

首次创建管理员账号（把密码换成你自己的）：

```bash
curl -X POST http://127.0.0.1:3005/api/admin/setup \
  -H "Content-Type: application/json" \
  -d '{"password":"你的网站密码"}'
```

账号固定是 `admin`，密码就是你刚设的这个。

## 方式 B：Debian / Ubuntu 裸机一键

要求：root 权限、能访问外网。

```bash
cd qqrt-server
sudo bash deploy/deploy-qqrt.sh
```

脚本会依次：装 Node 22 → 装 ffmpeg / nginx / postgresql / pm2 → 交互问域名、子路径、端口、数据库账号 → 建库建表 → `npm ci && npm run build` → pm2 常驻 → 写 nginx 配置。

装完按提示：

```bash
pm2 status
pm2 logs qqwatchtest
curl http://127.0.0.1:3005/api/health
```

> 子路径部署（如 `https://example.com/qqbotwatch`）时，`.env` 的 `NEXT_PUBLIC_BASE_PATH` 必须和 nginx 的 `location` 完全一致，否则页面能开、接口 404。

## 方式 C：手动（已有 Node + Postgres）

```bash
cd qqrt-server
cp .env.example .env
vi .env          # 至少改 DATABASE_URL、PORT、NEXT_PUBLIC_BASE_PATH

npm ci
npx drizzle-kit push --force     # 建表
npm run build
node start-publish.js            # 或 pm2 start ecosystem.config.cjs
```

Node 版本要求 **>= 22**（`package.json` 里写的是 >=20，实际构建用 22 更稳）。

## 环境变量（.env）

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | PostgreSQL 连接串，如 `postgresql://user:pass@127.0.0.1:5432/qqrt_db` |
| `PORT` | Next 监听端口，默认 3005 |
| `NEXT_PUBLIC_BASE_PATH` | 子路径部署前缀（如 `/qqbotwatch`），根路径留空 |
| `DATA_DIR` | 媒体缓存目录，默认 `./data` |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error` |
| `MAX_UPLOAD_MB` | 单次上传上限，默认 100 |
| `PG_POOL_MAX` | 连接池上限，真 Postgres 建议 10，PGlite 内嵌库用 4 |

## 手表 / 模拟器怎么连

| 场景 | 服务器地址填 |
|---|---|
| 手表与服务器同局域网 | `http://192.168.x.x:3005` |
| 公网 + 域名 | `https://your.domain`（子路径则 `https://your.domain/qqbotwatch`） |
| AIoT-IDE 模拟器 | `http://10.0.2.2:3005`（QEMU 映射宿主机，不通就填局域网 IP） |

登录用 `admin` + 你设的网站密码。**机器人 AppID/AppSecret 在网页控制台里填**，不是手表上填。

## 备份与迁移

```bash
# 数据库
pg_dump -U qqrt qqrt > qqrt-$(date +%F).sql

# 媒体缓存 + 密钥（data/ 里的 secret.key 丢了，已保存的 AppSecret 就解不开，需要重新绑机器人）
tar czf qqrt-data-$(date +%F).tar.gz data/
```

Docker 部署对应的是 `qqrt-db` 数据卷和 `qqrt-app` 的 `/app/data` 卷。

## 常见问题

**1. `/api/health` 返回 `{"ok":false}`**
数据库连不上。检查 Postgres 是否在跑、`DATABASE_URL` 的库名/密码/端口，Docker 部署时主机名必须是 `db` 而不是 `127.0.0.1`。

**2. 启动报 `listen EADDRINUSE`**
端口被占：`netstat -tlnp | grep 3005`，杀掉旧进程或改 `PORT`。

**3. 日志刷 `sync group list failed ... 不支持的调用`**
QQ 开放平台没给机器人开通「获取群列表」权限，**不是故障**：群名会在收到群消息时用 `/v2/groups/{group_openid}/info` 解析，收发消息不受影响。（新版已把这条降为 INFO。）

**4. 手表能登录但收不到消息**
机器人没连上。看日志有没有 `bot connected`；在网页控制台确认 AppID/AppSecret 正确、机器人已上线、消息接收开关为开。

**5. 图片消息显示灰块**
服务端下载不到 QQ 图片。检查服务器出网（`curl -I https://multimedia.nt.qq.com.cn`），以及 `data/` 目录可写；ffmpeg 缺失只会影响转码，不影响文本。

**6. 页面能打开但接口全 404**
`NEXT_PUBLIC_BASE_PATH` 与 nginx `location` 不一致，两边必须完全相同（带不带结尾斜杠都算不同）。
