## 启动 / 停止

双击 **`启动服务端.cmd`**（同目录还有个英文名 `start.cmd`，内容一样）。
一个窗口里同时起数据库和 Web 服务，**关窗口或 Ctrl+C 就全停**。

- 启动成功的标志：窗口里出现 `[qqrt] 数据库就绪，启动 Web 服务 0.0.0.0:3005 …`
  和 Next 的 `Ready in ...`，最后是 `Local: http://localhost:3005`
- 手动方式（调试用）：
  ```bash
  node pg-embedded.mjs      # 终端 1：数据库
  node start-publish.js     # 终端 2：Web/API
  ```
- 启动失败时窗口会停住并显示错误（不会闪退），把错误贴出来即可

> 之前闪退的原因已修复：① .cmd 用 UTF-8 保存，中文 Windows 的 cmd 按 GBK 解析导致整份脚本乱码；
> ② `start-publish.js` 里用 `spawn("node", ...)`，双击时 cmd 的 PATH 没有 node 会报 `ENOENT`。
> 现在 .cmd 是 GBK 编码，`start-publish.js` 改用 `process.execPath`。

## 首次使用

1. 浏览器打开 http://127.0.0.1:3005 ，用 `admin / qqrt123456` 登录；
2. 在网页里绑定 QQ 机器人（QQ 开放平台的 AppID + AppSecret），绑定后 `/api/watch/status` 会显示 `connected: true`；
3. 手表端（或模拟器）登录：
   - 服务器地址：`http://192.168.3.17:3005`（模拟器用 `http://10.0.2.2:3005`）
   - 账号 / 密码：`admin` / `qqrt123456`

> 地址**必须带 `http://`**：客户端在没写协议时会默认补 `https://`，那样会连不上。

## 数据与备份

- 数据库文件：`./pgdata`（整个目录拷走就是备份）
- 媒体/缓存：`./data`
- 想重置成全新库：停掉 `QQRT-DB`，删除 `./pgdata`，重新启动，再跑一次 `npx drizzle-kit push --force`

## 为什么不用 WorkBuddy 托管

- **Sites 托管**只提供单端口 HTTP 服务，预检明确拒绝带 `pg` / Postgres 连接串的项目（只支持 SQLite 或公网数据库），这个服务端会被直接判定为不可发布。
- **云服务**是 REST 风格的 Serverless 数据库（`/.cloud/database/rest/**`），不是 Postgres 连接串，drizzle + `pg` 用不了；要迁就得重写整个 repo 层。
- 另外这个服务端还跑着 QQ 机器人的长连接和本地媒体转码，本来也不适合无状态的 Serverless 环境。

所以这里采用「内嵌 Postgres + 本地进程」的方案：零安装、可随时删、和正式部署的差别只有一个 `DATABASE_URL`。

## 换成正式 PostgreSQL 时

只改 `.env`：

```env
DATABASE_URL=postgresql://用户:密码@主机:5432/库名
```

然后 `npx drizzle-kit push` → `npm run build` → `node start-publish.js`。代码不用动。

## 已知限制

- PGlite 是**单连接 + 查询队列多路复用**，并发高时会排队；适合本地测试和几个人用，不适合多用户生产负载。
- 内嵌库是 PG 18 的 WASM 构建，个别扩展（如 `pg_trgm`）不可用；当前 schema 没用到扩展。
- 机器人未绑定时，会话列表为空是正常的（没有消息源）。
